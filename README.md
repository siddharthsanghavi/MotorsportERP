# MotorsportERP
ERP workspace for an FSAE Formula car team.

## Web app MVP

Open `index.html` in a browser (or serve the folder with any static file server). The app uses browser `localStorage`, so it needs no backend setup.

Each section is its own static page (`index.html` is the Overview, then `design.html`, `events.html`, `parts.html`, `assembly.html`, `documents.html`, `approvals.html`, `machine-shop.html` (Manufacturing), `stock.html`, `testing.html`, `purchasing.html`, `vendors.html`, `budget.html`, `team.html`, and `guide.html`, a how-to for every page). Every page loads the same scripts (`app.js`, `ops.js`, `vendors.js`, `vehicles.js`, `manufacturing.js`, `carlog.js`, `funds.js`, `bugs.js`, `design.js`, `events.js`, `ui.js`) but only draws its own section. React and React Flow are fetched only when a map is on screen (an opened "How it works" map, the assembly graph, or the team map). The header and sidebar are repeated in each page, so a nav change has to be made in every file.

Pages share data through `localStorage`, which works across local files in Chrome and Edge. Firefox may keep a separate store for each local file, so use Chrome/Edge or serve the folder (for example `npx serve`) if data doesn't carry between pages.

### Modules

- Design (design.html): propose a design project, then move it through Proposed → PP1 → PP2 → PP3 → Manufacturing. Each PP gate passes a subteam review (subteam lead) and then a chief review (Chief Mechanic, President, VP or Admin). Either review can reject with a reason, the subteam lead can request changes, and the chief can send a project back to subteam review. The POC can't sign off their own gate. Cards show what the project is, its status and the latest comments. Tasks and team details stay hidden until you click them. Subteam and POC names link to the Team page (`team.html?subteam=…` / `?member=…`). The design timeline is a Gantt of history only: it shows the stages each project has actually reached up to today, with a milestone marker at each one.
- Parts by car: click a car (KS10, KS10E, or any car you add) to see its FSAE cost systems, then a system to see its assemblies, then an assembly to see and add its parts. Part numbers are generated as car-system-number (e.g. KS10-BR-001) when left blank. Each part belongs to one car. "Export cost BOM" downloads a CSV for that car, grouped by system and assembly, for the official FSAE cost report. A search box finds any part across all cars.
- BOM import/export: load a CSV (file or pasted from a spreadsheet) from SolidWorks, Onshape, Fusion, etc. Columns (Car, System, Assembly…) are matched by name and can be remapped in a preview; systems can be given by name or code (BR, DT, FR, EL, MS, ST, SU, WT); existing part numbers can be updated in place. Export the current BOM as CSV.
- Documents: register drawings, analyses, test reports, rules paperwork and more with auto-numbering (DOC-0001), links to the file, part/project links, and Draft → In Review → Released control with revision history. Authors can't release their own documents.
- Competition deliverables: checklist (SES, IAD, ESF, FMEA, cost report, design report…) linked to documents, with due dates and overdue warnings.
- Purchasing and vendors: purchase requests linked to a budget, part and project. Quotes over $500 need the President, VP or Chief Mechanic. Use "Order" on a part to pre-fill a request. Each request records its submit date, the budget it counts against and the fund it's paid from; an Admin approves the funds ("Approve funds") before it can be marked Ordered.
- Vendors (vendors.html): the supplier list with category, contact, website, lead time, terms and a preferred flag, plus spend, open orders and recent purchases per vendor. Purchase requests, stock items and part suppliers pick from it in a dropdown, and "+ Add a new vendor…" in the dropdown adds one on the spot. Anyone can add a vendor; Purchasing Approvers, Budget Managers and leadership can edit or delete them. Renaming a vendor updates every record that uses it.
- Manufacturing (machine-shop.html): anyone can request a part to be machined (part, qty, material, due date, CAD link, notes); the manufacturing lead is notified. Each job follows the shop checklist: the manufacturing lead fills it out (machinist, machine), the part goes into Fusion Hub, the lead approves the CAM, the job is run, deburred and checked in tolerance, bagged in the middle red cabinet, and the requester, the part's subteam lead and the manufacturing lead get a part-update notification. Only the manufacturing lead (or a Shop Lead) can tick the fill-out and CAM approval steps; the job status follows the checklist, and running a job still needs the machinist signed off on that machine.
- Tooling & consumables (Manufacturing tab): end mills, inserts, nuts and bolts with quantities, minimums, a main vendor and order link plus an alternate vendor and link. Using items counts them down; when one reaches its minimum the manufacturing lead is pinged and can reorder (which raises a purchase request).
- Budget: funding accounts (KSU Foundation, Fund 1300, Johnson, Department, Team total, PayPal, plus any you add) with available, spent, committed and remaining amounts, and budget categories. All spend comes from purchase requests; there's no manual spent figure. Admins and Budget Managers set account balances.
- Testing: log track sessions (car, event, driver, laps, km, setup notes, data-log link). Km are added to every installed part on that car, and issues become tasks on a project. Each session has a car log ("Start car log", or it opens right after you log a session) that saves as you type: what's being tested and why, known issues and run order; personnel (testing lead, drivers, ESOs, others); outside conditions; the pre-run car checks (mechanical, tractive battery, EV active, rain, brakes, diff fluid, cooling, driveline and suspension bolts) with issues; the setup sheet before the run and the setdown sheet after it (diff, motor/voltage, final drive, wing endplates, each corner's toe/camber/corner weight/tire pressure, suspension, shocks, toe, DRS), with "Copy setup from last session" and "Copy from setup"; laps per driver, a timing-sheet link and a conclusion. Roadmap: import an MCAP CSV export into the session.
- Part life & inspections (Parts tab): life limits and inspection intervals in km, safety-critical flags, inspection and replacement logging, and a failure log. Overdue items go to the right people's queue.
- Stock & tools: tools, consumables, spares and safety gear with check-out/check-in (blocked without the required training), consumable use, low-stock reorder that creates a purchase request and restocks on receipt, overdue returns, and printable QR labels with a scan box for USB scanners.
- Training sign-offs (Team tab): a member × training matrix that Shop Leads and the Chief Mechanic tick off.
- Notifications: an in-app bell for approvals, assignments, releases, failures and due-soon tasks.
- Edit any part, purchase, job, project or stock item in a dialog (who can edit follows the roles). Deletes ask for confirmation.
- Backup / Restore: download the whole workspace as JSON and restore it (Admin only). Data lives in this browser, so back up regularly.
- Design approvals: submit revisions for review and advance approval status
- Assembly: React Flow graph per car (car → system → assembly → part); drag from an assembly to a part to move it.
- Team map: React Flow org chart with President, Vice President, and Chief Mechanic at the top, 12 subteams (Low Voltage, EV Powertrain, Vehicle Dynamics, Suspension, Driver Interface, Frame, Driveline, Combustion, Aerodynamics, Composites, Manufacturing, Business) grouped under their leader, a lead per subteam, and members who can sit on several subteams. Demo roster names are generated and fictional.
- Team & roles: members hold roles (Admin, Purchasing Approver, Design Review Approver, Subteam Lead, Budget Manager, Shop Lead); switch "Acting as" in the header to see each person's permissions. Approvers can't sign off their own requests. Roles are enforced in the page only, not as real security.
- Demo controls: load realistic records across every module or clear the local workspace
- Events: track days the team hosts and competitions it attends. Each event has a lead, a roster with roles (volunteering for hosted days is open; travel spots for competitions need the lead to confirm, and capacity is enforced), a checklist whose due dates count back from the start date, a packing list linked to stock, an incident log, results and points for competitions, and the test sessions run there. You can request the entry fee as a purchase, events appear on the season timeline, and overdue checklist items and upcoming events show up in people's queues.
- Overview dashboard with counts, a "waiting on you" queue, and an audit log of who did what
- Bug reports: the 🐞 button in the header on every page records the page, severity, steps and expected result. Admins triage them under Workspace ▾ → Bug reports (status, CSV export, open as a GitHub issue) and reporters are notified when theirs is fixed.
- Guide (last tab): how to use each page.

The maps load React and React Flow from unpkg on demand, so they need an internet connection; QR labels use qrcode-generator from cdnjs. Everything else works offline.
